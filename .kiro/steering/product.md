# Product Overview

> 2026-11-08 同期。project-foundation と core-parser は初版の方式（`static const` の宣言テーブル、静的ライブラリのみ）で実装済みだが、2026-11-08 の改訂（roadmap.md の Approach Decision）で、共有ライブラリへの対応と、ビルダー API + 不透明ハンドルへの作り直しが決まった。本ファイルは改訂後の目指す姿を正とする。既存のコードとの差は、roadmap.md の「Existing Spec Updates」で解消する。

CLOpts は、C99 で書かれた外部依存ゼロのコマンドライン引数パーサライブラリである。呼び出し側はビルダー API（`clopts_program_new` から始めて、サブコマンド・オプション・位置引数を関数で追加する）で宣言を組み立てるだけで、解析・ヘルプ文面・エラーの 3 つが同じ宣言から決まる。静的ライブラリとしても共有ライブラリとしても使え、1.0.0 以降は共有ライブラリの ABI 後方互換を保証する。出発点は [Monde](https://github.com/ktdevx/monde-private) の内部モジュール `cli_args` だが、そのまま抜き出すのではなく、コマンドライン引数を扱うソフトウェア一般のための設計に作り直す。

- 著作権者: The CLOpts Authors ／ ライセンス: MIT License
- 利用者: MSVC を含む複数のコンパイラで動く CLI ツールを C で書く開発者。`getopt` がなく外部ライブラリにも頼れない環境を想定する。

## Core Capabilities

- **宣言からの解析**: サブコマンドあり／なしの両構成、サブコマンド前のグローバルオプション、長いオプション（`--name`、`--name=value`）、短いオプション（`-o v`、`-ov`、`-abc` のまとめ書き）、`--` による終端、位置引数とオプションの混在。
- **値の種類と出所**: フラグ、カウントフラグ（`-vvv`）、単一値、区切り文字付きリスト値、`--no-<name>` による否定、既定値、環境変数フォールバック。優先順位は明示指定 > 環境変数 > 既定値で、値ごとに出所を判別できる。
- **構造化エラーと宣言検査**: 使い方の誤りは構造化エラーとして返り、種別・該当コマンド・該当オプション・該当トークン・argv 添字をアクセサで読める。宣言の誤り（重複、予約名との衝突など）は使い方エラーと区別して返る。ライブラリは stdout / stderr に書かず、`exit` もしない。
- **宣言からの文面生成**: ヘルプ・使い方・バージョン・エラー文面を、書き込みコールバックに対して決定的な英語で生成する。`FILE*` に出すときは、公開ヘッダにある `static inline` のコールバックを渡すだけでよい。
- **Windows での UTF-8**: `main` の argv を使わず、コマンドライン文字列を現行 MSVC CRT の規則で分割して UTF-8 に変換する。環境変数も UTF-8 で返す。
- **静的／共有と ABI 互換**: `CLOPTS_BUILD_SHARED` で静的／共有を選べる。公開 API は不透明ハンドルと関数だけでできていて、1.0.0 以降は共有ライブラリを差し替えても利用側を再ビルドしなくてよい。

## Target Use Cases

- 4〜10 個程度のサブコマンドとそれぞれのオプションを持つ CLI ツール（Monde の `extract` / `init` / `update` / `translate` のような構成）。
- サブコマンドを持たない単純なフィルタ型ツール（`tool [options] FILE...`）。
- Windows / macOS / Linux に同じソースで配布し、日本語のファイル名など非 ASCII の引数を正しく受け取りたいツール。
- 利用側が独自の書式（`prog: error: ...`、色付け、ログへの転送）でエラーを表示したいツール。構造化エラーと書き込みコールバックがこれを支える。

## Value Proposition

- **宣言と挙動とヘルプが一致する**: オプションを追加・変更するとき、変えるのは宣言の 1 か所だけでよい。
- **利用側が表示と終了コードを決められる**: エラーは文字列ではなく構造化エラーとして返る。Monde で必要だった「ライブラリが付けた接頭辞を剥がして再整形する」処理が不要になる。
- **型で守られた値の参照**: 値は、宣言したときに返るオプションハンドルで参照する。文字列キーの打ち間違いが黙って NULL になることがない。
- **取り込みやすい**: `add_subdirectory` / `FetchContent` / `find_package(CLOpts CONFIG)` のどれでも `target_link_libraries(app PRIVATE CLOpts::clopts)` だけで使え、利用側のビルド設定（CRT 種別、C 規格、警告）を汚さない。静的／共有はどちらの経路でも選べる。
- **ABI が安定している**: 公開ヘッダに構造体の中身を出さず、属性の追加は関数の追加で行う。ライブラリが確保したメモリはライブラリが解放し、`FILE*` を DLL の境界越しに渡さない。そのため Windows で CRT が違っても壊れない。
- **依存ゼロ**: C 標準ライブラリと、Windows では kernel32 の API のみ。shell32 にも依存しない。

## Product Rules（挙動の既定）

- `--` 以降はすべて位置引数。`-` 単体は位置引数。
- サブコマンド名より前に置けるのはグローバルオプションだけ。サブコマンド以降はオプションと位置引数を自由に並べ替えられる。
- 長いオプションの前方一致による省略は行わない。大文字小文字は区別する。
- 単一値のオプションを繰り返すと後勝ち、リスト値は連結、フラグは重複を許す、カウントは上限でクランプする。
- `--help` / `-h` / `help <cmd>` / `--version` の要求は他の使い方エラーに優先し、状態として返る。
- 最初に見つけた使い方エラーだけを報告する。
- 値は文字列として返す。型変換・妥当性検査（整数、選択肢、範囲）は初版の境界外（roadmap.md の Future Phases を参照）。
